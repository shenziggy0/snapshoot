## 2026-11-03｜Snapshoot｜macOS 临时签名安装拦截与升级权限迁移
- 标签：#mistake #macOS #代码签名 #TCC #Tauri
- 状态：待验证

### 问题现场
用户安装 v1.1.0 时遇到“文件已损坏”，重装后需要重新授予权限。期望安装时能看到处理说明，更新后自动清除本应用旧授权并引导重新授权。

### 根因
本机 /Applications/Snapshoot.app 的版本为 1.1.0，签名显示 adhoc、linker-signed、TeamIdentifier 未设置、Sealed Resources 为 none；codesign --verify --deep --strict 报告资源封装不完整。应用带有 com.apple.quarantine。原发布流水线直接生成未正式签名、公证的 DMG，没有完整应用签名校验和随包安装说明。
应用的 designated requirement 绑定 cdhash。重新构建后哈希变化可能导致旧 TCC 授权不再匹配；此机制有 Apple 官方说明支持，但未读取本机 TCC 数据库，因此用户该次权限失效的具体匹配结果仍待验证。仅移除 quarantine 不等于修复签名或证明文件完好。

### 修复与验证
新增 scripts/package_macos.py：复制构建好的 .app，先签 OCR Mach-O 资源再签外层应用，使用 codesign --verify --deep --strict 校验，生成含“安装前请阅读 - Read Me.txt”和 Applications 链接的 DMG，再检查镜像校验和。三个 macOS 打包流水线使用统一脚本。
新增 macos_permissions.rs：正式构建在版本变更或旧版迁移后的首次启动，以 bundle identifier 为作用域调用 tccutil reset ScreenCapture 和 Accessibility。执行前持久化版本标记，避免部分失败或重启反复清除新授权；无法保存标记则跳过重置。开发与 smoke 运行不重置；全新安装仅记录版本。系统弹窗引导重新授权，失败提供手动移除旧条目的步骤。
更新窗口与 README 增加安装、更新权限说明。
验证结果：2 项 Rust 测试通过（版本切换/首次安装/迁移判断、尝试标记持久化与保存失败）；前端生产构建通过；三个 workflow YAML 可解析；使用本机旧版应用的副本生成测试 DMG，挂载后安装说明、Applications 链接及完整签名校验通过。未替换已安装应用，未实际重置用户权限；尚未完成新版真实升级授权的端到端验证，未发布新版。

### 下次如何避免
- macOS 发布必须走统一打包脚本，在全部资源装配完成后签名，签名验证失败不得生成发布产物。
- 每次发布新构建同步提升版本号；同版本重新构建不会触发这套基于版本号的权限迁移。
- 发布前用已授权旧版覆盖升级新版，验证只重置本应用两项权限、重新授权后截图/滚动/录屏可用，再重启确认不会再次清除。
- 检查全新安装不做升级重置；模拟 tccutil 失败时仍显示恢复步骤且下一次启动不循环重置；检查无法持久化标记时不执行清除。
- 从浏览器下载实际发布 DMG，确认未启动应用也能读到安装说明。临时签名仍可能被 Gatekeeper 拦截，不宣称获得 Apple 公证。

### 实机验收补记（2026-11-03）
用户确认 Apple 芯片版 DMG 的本机验收全部通过。验收包括覆盖安装、首次启动重新授权、从菜单栏恢复权限、截图／滚动长截图／录屏，以及同一构建重启不重复清除。最终实现以版本和代码签名指纹共同识别构建，补充了逐项权限检查及失败项重试。整体状态更新为已验证修复。Apple 公证不在本次验收范围内。
